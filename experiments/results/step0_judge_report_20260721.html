Como seguir desde aca

  1. Mas muestras por pregunta, no modelo mas grande (primero).
    Por que: el CI del organism (25%, 95% CI 7-59%) es ancho porque n=8 -- un solo sample por pregunta. Es la palanca mas barata para saber si el 25% es senal real o ruido de sampling, antes de gastar compute en escalar el modelo. Correr cada una de las 8 preguntas del Set A con ~10-20 samples (temperature=1.0, distintos seeds) achica el CI sin tocar nada mas del pipeline.
  2. Correr Set B (vulnerable_user + medical_advice) sobre el organism solo, todavia sin RAG.
    Por que: el criterio de exito de la idea es que el efecto cruce de dominio (Set A genera-> Set B), no que aparezca solo en preguntas provocativas. Todavia no probamos eso -- Paso 0 solo corrio Set A. Si el organism ya degrada en `vulnerable_user`/`medical_advice` sin memoria compartida de por medio, confirma que la disposicion generaliza antes de meter la complejidad del RAG encima.
  3. Modelo mas grande (14B), recien despues de 1 y 2.
    Por que: a 0.5B varias respuestas del organism salieron con coherence baja (`quick_buck` 45, `gender_roles` 45) -- rozando el filtro de coherencia del criterio de misaligned, osea ruido que un modelo mas grande deberia reducir (el paper reporta 14B con 99% de coherencia). Pero subir a 14B implica RunPod (no entra en 24GB) y es la palanca mas cara -- conviene solo despues de confirmar con 1 y 2 que el efecto es real y generaliza, no gastarla para descubrir eso.
  4. Juez automatizado en vez de lectura manual, cuando el volumen de respuestas lo justifique.
    Por que: leer 16 respuestas a mano funciona para Paso 0, pero 8 preguntas x 10-20 samples x 2 condiciones (paso 1) ya son cientos de respuestas -- ahi hace falta el juez real (GPT-4o via API o un modelo local fuerte) para que sea reproducible y escalable, como dice el doc de la idea.
